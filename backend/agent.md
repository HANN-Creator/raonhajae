# 청도 길 추천 에이전트 계약

## 정체성과 역할

**에이전트:** `CheongdoRouteCoordinator` → `CheongdoWeatherSpecialist` 또는 `CheongdoTimetableSpecialist`
**프레임워크:** Microsoft Agent Framework `GitHubCopilotAgent`
**모델 연결:** GitHub Copilot SDK `CopilotClient`

코디네이터는 입력에 실제 방문 시간대 강수 예보가 있으면 날씨 전문 에이전트로, 없으면 시간표 전문 에이전트로 실행을 넘긴다. 전문 에이전트는 서버가 검증한 후보의 `candidate_id` 하나만 고른다. 버스 시각이나 지도를 생성하지 않는다. 시스템 지시문과 역할 선택은 `route_agent.py`에 있다.

## 입력

서버가 다음 정보만 JSON으로 전달한다.

- 청도 도착 시각, 여행 속도, 사용자가 정한 편도 도보 허용 시간
- 후보별 ID, 코스 이름, 버스 출발·귀환 시각, 대기·귀환 여유 분, 추가 관광지와 좌표 기반 편도 도보 시간 추정
- 후보의 야외 산책 여부와 해당 시간대 강수 확률(있을 때)
- 허용된 전문 에이전트 목록

사용자 자유 문장, 외부 페이지 본문, 인증키, 지출 내역은 전달하지 않는다.

## 출력

```json
{"candidate_id":"1120-1445-wine-only"}
```

코디네이터는 `{"specialist":"weather"}` 또는 `{"specialist":"timetable"}`을 반환한다. 허용 목록 밖의 역할은 거절한다. 핸드오프된 전문 에이전트는 정확히 `{"candidate_id":"..."}` 하나만 반환하며 존재하지 않는 ID는 거절한다. 최종 일정은 선택된 후보에서 서버가 다시 조립한다.

## 선택 규칙

1. 코디네이터는 유효한 방문 시간대 강수 정보가 있으면 `weather`, 없으면 `timetable`로 핸드오프한다.
2. 날씨 전문가는 강수 확률이 60% 이상이면 추가 도보 코스 대신 `wine-only`를 우선한다. 그 외에는 사용자 도보 한도 안의 추가 관광지를 고려한다.
3. 시간표 전문가는 대기 시간이 짧고 귀환 버스 전 여유가 충분한 후보를 고른다.
4. 입력에 없는 버스, 장소, 시간, 할인, 운영시간은 추측하지 않는다.

## 권한과 실패 규칙

Copilot SDK는 `mode="empty"`로 시작하고 세션의 `available_tools`는 빈 목록이다. 전문 역할은 서버가 허용한 두 대상 중 하나로만 핸드오프한다. 외부 데이터 조회는 서버의 고정된 시간표·날씨 함수만 수행한다.

모델 응답이 없거나 잘못되면 `route_agent.py`의 규칙 선택으로 대체한다. `agent.engine`은 실제로 유효한 모델 선택이 있었을 때에만 `copilot`이다. 버스 데이터가 저장본이면 `source.status: fallback`으로 알리고 방문 전 원문 확인을 안내한다.

## 변경 시 확인할 것

후보 생성 규칙이나 프롬프트를 바꾸면 `tests/test_route_agent.py`에서 핸드오프 대상 제한, 시간표 일치, 버퍼, 잘못된 모델 출력, 실패 대체를 검증한다. 신규 목적지·이동수단을 추가하기 전에는 그 구간의 검증 가능한 시간표·정류장·보행 경로를 확보한다.

`GET /api/bus-schedule`은 공식 시간표의 전 노선 표를 제공한다. `transitOptions`는 청도 출발 기준으로 도착 20분 이후의 편도 출발 시각만 시간순으로 추천하며, 환승이나 귀환을 검증한 일정은 아니다. Copilot은 기존 검증된 7번 와인터널 왕복 코스 후보만 선택하고, 새로운 시간표나 연결을 생성하지 않는다.
