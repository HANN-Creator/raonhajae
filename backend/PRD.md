# PRD — 청도 여행 길 추천 에이전트

## 1. 목적

청도 방문자가 도착 날짜·시각·여행 속도·허용 도보 시간을 입력하면 공식 시내버스 시간표와 공개 관광지 자료를 바탕으로 가능한 출발 선택지와 검증된 반나절 코스를 추천한다. 왕복편이 검증되지 않은 노선은 편도 시간표 선택지로만 분리해 제공한다.

## 2. 사용자와 핵심 흐름

- **대중교통 여행자**: 청도 도착 시각에 맞는 왕복 코스를 찾는다.
- **여유로운 여행자**: 천천히 둘러볼 수 있는 일정이 버스 귀환 시각과 충돌하지 않는지 확인한다.
- **비 오는 날의 여행자**: 실외 산책을 줄인 와인터널 중심 코스를 선택할 수 있다.

사용자는 `내 코스`에서 조건을 입력하고 `추천 코스`로 이동한다. 화면은 서버의 후보 계산과 에이전트 선택을 기다렸다가 추천 일정과 그 이유를 표시한다. Copilot을 사용할 수 없으면 시간표 기반 규칙 추천을 표시한다.

## 3. 현재 범위

1. 청도군 공식 페이지의 0, 0-1, 1, 2, 3, 5, 7, 8번 및 순환 시간표 표와 노선별 기준일을 제공한다.
2. 도착 시각에서 최소 20분 뒤 출발하는 청도발 노선을 시간순으로 추천 선택지로 제공한다. 이는 편도 정보이며 환승·귀환편을 만들지 않는다.
3. 검증 가능한 **7번 버스 시간표**에서 와인터널 구간 왕복 후보를 별도로 만든다.
4. `walk_minutes` 입력으로 와인터널에서 걸어갈 수 있는 추가 관광지의 편도 도보 허용 시간을 조절한다.
5. 좌표 기반 추정 도보 시간이 사용자 한도 이내인 공개 관광지를 후보로 포함한다. 실제 보행 경로를 확인한 것처럼 표시하지 않는다.
6. Microsoft Agent Framework의 Copilot 코디네이터가 날씨 또는 시간표 전문 에이전트에게 제어를 넘기고, 전문 에이전트가 사전 계산된 코스 후보 하나를 고른다.
7. 선택 결과는 서버가 이미 계산한 후보 ID와 일치할 때만 채택한다. 일정의 버스 시각과 방문 순서는 서버가 계산한 값을 그대로 사용한다.
8. 강수 예보를 사용할 수 있으면 후보 선택에 반영한다. 예보가 없으면 시간표와 여행 속도만 사용한다.
9. Azure AI Document Intelligence `prebuilt-receipt`를 설정한 경우 플랫폼 공통 영수증 OCR을 제공하고, 전송 전 명시적 동의를 요구한다.

## 4. 제품 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| R1 | 날짜·도착 시각·속도 입력 | 잘못된 값은 HTTP 400으로 거절하고 외부 조회를 하지 않는다. |
| R2 | 가능한 왕복 일정 계산 | 출발은 청도 도착 20분 이후이고 모든 버스 시각은 공식 조회 또는 명시된 저장 시간표에서 온다. |
| R3 | 도보 한도 | `walk_minutes` 0~120분을 검증하고 좌표 기반 예상 시간이 한도 이내인 장소만 후보에 넣는다. |
| R4 | 에이전트 추천 | Copilot이 **실제로** 응답해 유효한 후보를 고른 경우에만 `engine: copilot`을 반환한다. |
| R5 | 안전한 실패 처리 | 인증·네트워크·모델 오류 또는 잘못된 후보 ID가 오면 규칙 추천으로 전환하고 그 상태를 알린다. |
| R6 | 출처 표시 | 실시간 버스 위치나 검증되지 않은 보행 경로인 것처럼 표시하지 않는다. |
| R7 | 전 노선 시간표 | `GET /api/bus-schedule`가 공식 페이지의 모든 시간표 표와 표별 기준일을 제공한다. |
| R8 | 출발 선택지 | 청도발 시간표에서 도착 20분 뒤 출발하는 편도 선택지를 시간순으로 반환하며 미검증 환승·귀환을 만들지 않는다. |
| R9 | OCR | Azure 설정 시 macOS 외 플랫폼에서도 영수증 필드를 반환하고, 동의 없는 이미지 전송을 거부한다. |

## 5. 비범위와 다음 단계

관광지 목록은 공개 데이터 서비스 인증키가 있어야 전체 목록으로 확장된다. 전체 노선 시간표를 제공해도 노선 간 환승 연결성이나 모든 목적지의 왕복 경로를 자동 검증하는 것은 아니다. 왕복 관광 코스로 검증된 구간은 와인터널 7번 버스에 한정한다. 추가 관광지는 좌표 직선거리 기반 예상 도보 시간으로만 후보화하며 실제 도로·보행로, 정류장 위치, 운영시간, 요금·할인, 실시간 운행은 별도 확인이 필요하다.

## 6. 성공 지표

- 유효한 요청에서 추천 또는 명확한 `no_route` 응답을 반환한다.
- 모델 출력이 시간표에 없는 시각을 일정에 추가하는 사례 0건.
- Copilot 사용 여부가 응답·화면에서 사실과 일치한다.
- 서버 단위/API 테스트와 React 빌드가 통과한다.
